# Interface translations (i18n)

Nova's interface ships in English, Spanish, French, German, Portuguese,
Simplified Chinese, and Japanese. Users pick their language in
**Settings → General → Language**; the choice is stored on the device
(`localStorage` key `nova.language`) and defaults to the browser language
when it is supported.

## How it works

- `client/src/i18n/en.ts` is the single source of truth: every translatable
  UI string lives there under a dotted key (`settings.billing.title`).
- `client/src/i18n/<locale>.ts` files are **machine-generated** from `en.ts`
  and committed. TypeScript checks that every locale mirrors every key.
- `useTranslation()` (from `client/src/contexts/LanguageContext.tsx`) returns
  `t(key, vars?)`, `tPlural(oneKey, otherKey, count, vars?)`, the active
  `language`, and a BCP-47 `locale` for date formatting. Lookups fall back to
  English. Outside a provider (unit tests) it safely returns English.
- `{{token}}` placeholders in a string are interpolated at render time and
  verified to survive translation intact.

## Adding or changing UI text

1. Add/change the string in `client/src/i18n/en.ts` and use `t("...")` in the
   component (see existing cards for the pattern).
2. Regenerate the other locales:

   ```sh
   pnpm i18n:translate            # only new/changed keys (incremental)
   pnpm i18n:translate es fr      # specific locales only
   pnpm i18n:translate -- --force # re-translate everything
   ```

3. Review the diff and commit `en.ts`, the touched locale files, and
   `client/src/i18n/manifest.json` (tracks per-key source hashes so re-runs
   stay incremental).

The generator (`scripts/translate-locales.ts`) uses an OpenAI-compatible chat
endpoint - Pollinations' free tier by default, no key needed (slow: one
completion every ~30s). Set `TRANSLATE_API_KEY` (or `POLLINATIONS_API_KEY`),
`TRANSLATE_API_BASE_URL`, and `TRANSLATE_MODEL` to go faster or use another
provider.

Speed is bounded by the tier's *output* budget: each reply is capped at about
1 500 tokens, and a reply that overruns it comes back truncated, burning a whole
paced request. Batches are therefore packed by an estimated token budget rather
than by a fixed string count.

- `TRANSLATE_TOKEN_BUDGET` (default 1250): output tokens a batch may cost.
  Lower it if replies still arrive truncated.
- `TRANSLATE_BATCH_SIZE` (default 120): ceiling on strings per completion.
- `TRANSLATE_CONCURRENCY` (default 4 with a key, 1 without): requests in flight
  and allowed per pacing window. The anonymous tier is capped per IP, so the
  script stays serial unless you provide a key - raise it to translate all
  locales in parallel.
- `TRANSLATE_PACE_MS`: window over which request starts are paced.

Every batch is written to `.cache/i18n-translations.json` (not committed) as it
lands, so an interrupted or rate-limited run resumes instead of re-requesting
work it already finished. A string that can't be translated correctly falls back
to English and is deliberately left out of the manifest, so a later run retries
it rather than freezing the English text in.

Hand-fixes to generated locale files survive incremental re-runs but are lost on
`--force`.

## Coverage

Translated today: the app shell (sidebar, header, More page), the username
prompt, the entire Settings page, and the public landing page. Other pages
still render their own hardcoded English strings; migrate them incrementally
by moving their text into `en.ts` and switching to `t()`.
